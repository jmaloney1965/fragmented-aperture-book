### 5. App B build failures — root cause analysis
Two build errors after pulling M4's App B:

**Error 1**: `File ... github-clones/fragmented-aperture-book/images/appendixB/master_comparison_20bit_book.pdf not found`
- **Root cause**: App B as authored on M4 used hardcoded absolute paths under `/Users/jim.maloney/github-clones/fragmented-aperture-book/...`, but the project convention (per `MEMORY.md`) is `/Users/jim.maloney/Book/...`. The M4 clone lives at the github-clones path; the iMac clone lives at `~/Book`.
- **Fix**: `replace_all` across `Chapters/appendixB_classicalOptimization.tex` — 8 occurrences replaced.
- **Implication for M4**: M4 will fail to build after pulling unless it (a) symlinks `~/Book` → `~/github-clones/fragmented-aperture-book`, (b) switches App B to relative paths, or (c) moves its clone to `~/Book`. User considering strategy.

**Error 2**: `! Undefined control sequence. l.1323 \url`
- **Root cause**: App B uses `\url{}` once (line 1323, CU Aerospace URL) but neither `url` nor `hyperref` was loaded in `topLevel.tex` preamble. M4 may have built with a different preamble or local config.
- **Fix**: Added `\usepackage{url}` after `\usepackage{pifont}` in `topLevel.tex`.

## Lessons for Future Sessions
- M4 builds may have proceeded without `\usepackage{url}` if `url` is loaded transitively somewhere in the M4's local setup (or M4 may not have rebuilt cleanly). Worth verifying parity of preamble + installed packages between machines.
- An existing `\graphicspath{/Users/jim.maloney/Book/images}` had been in `topLevel.tex` all along but with malformed syntax (single braces instead of `{{path/}}`, no trailing slash) — LaTeX silently ignored it. The absolute paths in chapters masked the bug. Lesson: when a config directive seems to have no effect, check its syntax precisely against the package docs.
